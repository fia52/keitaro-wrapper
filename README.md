# Keitaro Wrapper

Тестовое Adrobot: создание кампаний и редактор офферов через Admin API Keitaro.
Стек: Python 3.12+, FastAPI, SQLAlchemy 2, Alembic, HTTPX, Jinja2 и обычный JavaScript.
По умолчанию используется SQLite; отдельный сервер БД не нужен.

## Что делает приложение

Форма принимает название, двухбуквенный ISO-код страны и активный оффер Keitaro.
Сервер добавляет префикс `test_frolov_`, если его ещё нет, и создаёт кампанию:

1. Группа `FORTESTS`, домен `kylovoa.com`, источник трафика не задан.
2. Первый поток: регулярный, фильтр `country / accept`, HTTP 302 на
   `https://www.google.com/` для выбранной страны.
3. Второй поток: по умолчанию, без фильтров, выбранный оффер с долей 100%.
4. Кампания использует последовательную обработку потоков (`position`).

Кампания создаётся отключённой и включается после успешного создания потоков.
История в интерфейсе отображает операции этого приложения, а не все кампании трекера.
Редактор существующих кампаний доступен на странице /campaigns.

## Установка и запуск в WSL

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/getting-started/installation/).

```bash
cd ~/workspace/keitaro-wrapper
uv sync --locked
cp .env.example .env
```

Если `.env` уже настроен, копировать шаблон поверх него не нужно.
Укажите в `.env` значение `KEITARO_API_KEY`. Пример остальных настроек:

```dotenv
KEITARO_BASE_URL=https://tlgk.host
KEITARO_API_KEY=
KEITARO_DOMAIN=kylovoa.com
KEITARO_GROUP=FORTESTS
DATABASE_URL=sqlite:///./keitaro.db
```

Базовый URL задаётся без `/admin_api/v1`. Домен, группа и активный оффер должны
существовать в трекере. Приложение не создаёт справочники автоматически.
Для API-ключа нужны права чтения справочников, создания кампаний и потоков,
а также изменения кампаний. Секреты и файл SQLite исключены из Git.

```bash
uv run alembic upgrade head
uv run uvicorn keitaro_wrapper.main:create_app --factory --host 127.0.0.1 --port 8000
```

Откройте [интерфейс](http://localhost:8000) или
[Swagger UI приложения](http://localhost:8000/docs).
Приложение рассчитано на локальный запуск и не содержит пользовательской авторизации.
Миграции применяются явно; сервер не создаёт таблицы при запуске.

## Миграции

```bash
uv run alembic current
uv run alembic upgrade head
uv run alembic revision --autogenerate -m 'describe change'
```

Для отката начальной миграции: `uv run alembic downgrade base`.
Откат удалит локальный журнал операций, но не ресурсы в Keitaro.

## HTTP API

- `GET /health` — доступность процесса.
- `GET /api/catalog` — активные офферы и выбранные домен/группа.
- `POST /api/campaigns` — создание кампании.
- `GET /api/operations` — последние 30 операций.

Пример тела `POST /api/campaigns`:

```json
{
  "request_id": "625cd17b-6426-4e91-8f64-675007257a73",
  "name": "campaign1",
  "country_code": "DE",
  "offer_id": 18813
}
```

Используйте новый UUID для новой операции. Повтор с тем же UUID и теми же
нормализованными параметрами вернёт текущий результат без новых запросов на запись
в Keitaro; другие параметры с тем же UUID дадут HTTP 409. Некорректный ввод — 422.
Запущенный сценарий возвращает HTTP 200 с `status`: `completed`, `failed` или
`pending` при повторном запросе во время выполнения. Клиент должен проверять
поле `status`, а не только HTTP-код. Ошибки получения справочника: 502/503.

## Частичные сбои и повторные запросы

До первого внешнего изменения в БД резервируется `request_id`. После каждого
успешного изменения сохраняются ID кампании и потоков. Уникальный первичный ключ
защищает от одновременной отправки одного запроса. Браузер сохраняет незавершённую
команду в `sessionStorage`, чтобы повторная проверка использовала прежний UUID.

HTTP-запросы на запись автоматически не повторяются. При сетевом тайм-ауте Keitaro
может уже создать ресурс, но приложение ещё не знает его ID. При сбое активации
кампания может уже оказаться включена. Между внешним HTTP-вызовом и записью в БД
также остаётся окно сбоя; общей транзакции у двух систем нет.

При `failed` или оставшемся после остановки процесса `pending` проверьте кампанию
в Keitaro по имени/ID перед новой операцией. Не удаляйте запись ради повторного
запуска: это снимает защиту от дублей. Автоматическое восстановление или удаление
частично созданных ресурсов не выполняется; известные ID доступны в JSON истории.
Содержимое ошибок upstream и API-ключ не возвращаются пользователю.

## Архитектура

```text
src/keitaro_wrapper/
├── domain/             # Команда, состояние операции, собственные ошибки
├── application/        # Сценарий и абстрактные порты трекера/репозитория
├── infrastructure/     # Адаптер Keitaro и SQLAlchemy
├── presentation/       # HTTP-схемы, маршруты, HTML, CSS, JS
├── config.py           # Настройки окружения
└── main.py             # Сборка зависимостей и жизненный цикл
```

Application зависит от domain. Infrastructure реализует порты application.
Presentation вызывает сценарии, не выполняя HTTP-запросы к трекеру или SQL.
Конкретные зависимости связываются в `main.py`. Сессия БД выделяется на запрос.

## Проверка

```bash
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
```

Тесты используют SQLite во временной директории и HTTPX MockTransport.
Они не обращаются к реальному Keitaro. Проверяются параметры потоков, порядок
активации, идемпотентность, конфликты UUID, валидация и ошибки каждого этапа.

Документация интеграции:
[официальный Keitaro Admin API](https://admin-api.docs.keitaro.io/).

## Редактор кампаний и офферов

Откройте [список кампаний](http://localhost:8000/campaigns). По умолчанию видны
кампании с префиксом `test_frolov_`; переключатель «Все кампании» снимает фильтр.
Поиск работает по названию или ID. В редакторе отображаются существующие потоки:
потоки без офферов, в том числе Google, доступны только для просмотра.

Изменения сохраняются в SQLite автоматически и переживают перезагрузку страницы.
Жёлтая карточка потока обозначает отличия от последнего подтверждённого снимка.
До нажатия **Push KT** состав офферов в Keitaro не меняется. Публикуется один поток;
фильтры, лендинги и настройки самого потока не редактируются.

- «Добавить оффер» ищет активные офферы по ID или названию (до 100 совпадений).
- «Удалить» переносит оффер в локальный архив с долей 0%.
- «Вернуть» возвращает архивный оффер, если он ещё активен в каталоге Keitaro.
- «Отменить» возвращает состав и доли к последнему подтверждённому снимку.
- «Обновить из Keitaro» перечитывает потоки. При наличии черновиков сначала
  опубликуйте или отмените их. Офферы, удалённые непосредственно в Keitaro,
  сохраняются в локальном архиве.
- «Перечитать черновики» обновляет данные из локальной БД, например после
  конфликта с другой вкладкой.

Архив сохраняется после Push и повторной синхронизации. Удаляется только связь
оффера с потоком; сам оффер из каталога Keitaro не удаляется. История начинается
с первого чтения потока обёрткой: ранее удалённые неизвестные офферы восстановить
из неё нельзя. Создание, удаление и восстановление самих потоков не реализуются.

### Доли и булавки

Доли задаются целыми числами 0–100. При добавлении, удалении и возврате остаток
после закреплённых долей делится поровну между незакреплёнными офферами.
Остаток округления получают первые офферы в сохранённом порядке:
например, 34/33/33 или 25/38/37 при закреплённых 25%.

Ручной ввод сохраняет введённую долю и перераспределяет оставшиеся незакреплённые
доли. Для сохранения значения при последующих операциях нажмите булавку.
Фиксации хранятся локально и сохраняются после Push. Сама булавка не требует
публикации, поскольку не меняет доли в Keitaro. Если долю закреплённого оффера
изменили непосредственно в Keitaro, при синхронизации его фиксация снимается.

Невозможное распределение отклоняется целиком: например, закреплённая сумма
превышает 100% либо все оставшиеся офферы закреплены с суммой меньше 100%.
Сначала открепите один из офферов. Пустой черновик допустим, но его нельзя
опубликовать: верните или добавьте оффер. Для Push сумма активных долей должна
равняться 100%.

### Конфликты и сбои Push

Каждая команда содержит ревизию черновика. Запись из устаревшей вкладки
возвращает HTTP 409. Перед Push приложение фиксирует локальную блокировку,
затем сравнивает свежий поток Keitaro с исходным снимком. Внешние изменения
вызывают 409: отмените черновик и обновите данные перед новой правкой.

После PUT результат перечитывается. При сетевом сбое черновик помечается
неопределённым: автоматического повторного PUT нет. «Сверить после сбоя»:
если Keitaro уже принял состав, подтверждает публикацию; если там исходный
состав, сохраняет черновик для новой явной попытки. Если данные отличаются
от обоих состояний, проверьте их и используйте «Принять состояние Keitaro»,
чтобы явно отбросить неопубликованные изменения, сохранив архив.

После аварийного завершения процесса блокировка Push снимается сверкой
не раньше чем через две минуты после начала операции. Ревизии защищают
от конкурирующих запросов обёртки, но Keitaro не предоставляет общей транзакции
с нашей БД: изменение через админку между проверкой и PUT всё ещё возможно.
Проверка после записи обнаруживает несовпадение, но не устраняет эту гонку.
Удаление целого потока в Keitaro обнаруживается при обновлении; его локальная
история сохраняется, автоматическое восстановление потока не выполняется.

### API редактора

- `GET /api/campaigns?all_campaigns=false&q=` — список кампаний.
- `GET /api/offers?q=` — поиск активных офферов.
- `GET /api/campaigns/{campaign_id}/streams` — сохранённые потоки; первое
  обращение импортирует их из Keitaro.
- `GET /api/campaigns/{campaign_id}/streams?refresh=true` — явная синхронизация.
- `POST /api/campaigns/{campaign_id}/streams/{stream_id}` — команда редактора.

Пример команды:

```json
{"revision": 2, "action": "share", "offer_id": 18813, "share": 25}
```

Действия: `add`, `restore`, `remove`, `pin`, `share`, `push`, `cancel`,
`recover`, `reset`. ID оффера нужен для операций над оффером, `share` — для
ввода доли. Успешный ответ содержит обновлённый поток и новую `revision`.
Ошибки: 422 — недопустимая операция/ввод, 409 — конфликт, 502 — сбой Keitaro.

Редактору нужны права чтения кампаний, потоков и офферов и обновления потоков.
Перед запуском обновлённого приложения выполните `uv run alembic upgrade head`.
Миграция `0002` добавляет только локальную таблицу `stream_drafts`.
Для отката только редактора: `uv run alembic downgrade 0001`
(удаляет черновики, фиксации и локальный архив, не меняет Keitaro).
